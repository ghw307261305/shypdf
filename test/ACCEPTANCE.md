# ShyPDF 本地验收测试

23 个工具全部在浏览器里跑，所以验收 = 在真实浏览器里点一遍。这份清单分三层：

1. **通用 pattern**（P1–P12）：每个工具都要过，别的章节不再重复。
2. **逐工具用例**：只写该工具特有的东西。
3. **站点级**：多语言、隐私卖点、报错邮件、兼容性。

> **自动化**：这份清单里的大部分用例已经写成可重跑的脚本，见 [`test/acceptance/`](acceptance/README.md)
> （`BASE=http://localhost:4322 npm run test:accept`）。手工只需要补跑它覆盖不到的部分：真人触屏、
> 多浏览器（Safari / Firefox）、以及肉眼看版式。执行记录见文末「第 5 节」。

## 0. 准备

```bash
node scripts/make-fixtures.mjs     # 生成素材到 test/fixtures/（约 100 MB，已 gitignore）
npx tsx test/_verify-fixtures.ts   # 可选：确认素材本身符合预期
npm test                           # Node 侧冒烟测试先过
npm run dev                        # http://localhost:4321/
```

素材清单见 `test/fixtures/README.md`。下文用 `pdf/text-5p.pdf` 这种相对路径指代。

验收时**始终开着 DevTools**：Network 面板用来确认没有文件外传（除 OCR 语言包和字体），Console 面板用来发现没冒泡到界面上的异常。

## 1. 通用 pattern（每个工具跑一遍）

| # | pattern | 做法 | 期望 |
| --- | --- | --- | --- |
| P1 | 三种投喂方式 | ① 点「选择文件」② 拖到上传区 ③ 在文件列表阶段再拖一个进来 | 三种都进得去；拖拽时上传区有高亮态 |
| P2 | 类型不符 | 传 `bad/not-a-pdf.pdf`（PDF 工具）或 `bad/not-an-image.jpg`（图片工具）；再试 `office/report-rich.docx` 传给 PDF 工具 | 上传区红字「不支持」并带文件名；不进入下一阶段；Console 无未捕获异常 |
| P3 | 超过体积上限 | 传 `bad/oversize-53mb.pdf` | 提示超过 50 MB；不解析文件 |
| P4 | 超过数量上限 | 只对多文件工具：一次选 25 张图 | 收前 20 个，提示「最多 20 个文件」 |
| P5 | 列表操作 | ‹ › 换位、× 删除、拖拽排序、「按名称排序」、「清空」 | 序号跟着变；删到 0 个回到上传阶段；清空后再传能正常开始 |
| P6 | 缩略图 | 传 `pdf/photos-12p.pdf`、`pdf/text-60p-bookmarks.pdf` | 缩略图逐个出现、不阻塞界面；加密 / 损坏文件无缩略图但不报错 |
| P7 | 进度与禁用 | 跑 `pdf/photos-12p.pdf` 这类慢任务 | 进度文案 + 进度条推进；按钮置灰不可重复点击 |
| P8 | 结果页 | 任一成功任务 | 自动触发一次下载；文件名 / 体积正确；多输出打包 zip（≤6 个时额外列出单文件按钮）；首页预览图正确；「返回」回到选项、「重新开始」清空 |
| P9 | 输入校验报错 | 故意填错（页码范围越界、必填留空、密码相同…） | 红字是**中文/当前语言的友好提示**，不是英文异常堆栈；不发报错邮件（见 P12） |
| P10 | 加密文件兜底 | 把 `pdf/encrypted-user-pw-open123.pdf` 传给解锁以外的任意工具（run / 页面展开 / 自定义工作区三条路径各选一个） | 当前语言的友好提示 + 一个指向本语言解锁工具的链接，不是库的英文原文 |
| P11 | 离线 | 断网（DevTools → Offline）后跑一次 | 除 OCR 语言包 / qpdf / 字体首次加载外，功能照常；刷新后页面仍可用则更好 |
| P12 | 不上传文件 | 全程看 Network | 只有静态资源、`/vendor/*`、字体；**没有任何 POST 带文件**；唯一的 POST 是失败时的 `/api/error-report`，且其中不含文件内容 |

> P9 与 P12 是一对：`UserError`（用户输入问题）**不**上报；程序缺陷才发邮件。验收时至少确认一次「填错不发信」。

### 横切维度（按抽样跑，不必 23×N 全排列）

- **语言**：en / es / pt / fr / de / ja / zh / zh-tw。每个语言至少完整跑 1 个工具；重点看按钮文案、错误提示、体积单位（`1.5 MB` / `1,5 MB` / `1,5 Mo`）。
- **浏览器**：Chrome、Safari、Firefox 各跑一遍重工具（OCR / 压缩 / PDF↔Word）。Safari 的 canvas 内存最紧。
- **设备**：手机窄屏（Safari iOS）至少跑合并、拆分、图片转 PDF、签名——签名的手写板和拖放定位是触屏重灾区。

## 2. 逐工具用例

### 编辑类

**merge-pdf**（多文件，最少 2 个）

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 基本合并 | `text-5p` + `letter-3p` + `cjk-text-2p` | 10 页，顺序 = 卡片顺序；混合 A4/Letter 各页保持自己的尺寸 |
| 排序生效 | 上面三个，拖拽调序后再跑 | 页序跟着调整后的顺序 |
| 书签 | 勾选「加书签」 | 阅读器里 3 条一级书签，名字 = 文件名（不含扩展名） |
| 输出名 | 留空 / 填「我的文件」/ 填「x.pdf」 | 分别是默认名、`我的文件.pdf`、`x.pdf`（不出现 `x.pdf.pdf`） |
| 不足 2 个 | 只传 1 个 | 开始按钮置灰 |

**split-pdf**

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 每页一个 | `text-5p`，模式「每页」 | 5 个文件打包 zip |
| 范围 | `text-5p`，`1-2, 4` | 2 个文件（2 页 + 1 页） |
| 奇偶 | `text-5p`，奇数页 / 偶数页 | 3 页 / 2 页 |
| 越界 | `1-9` | 友好提示，不崩 |
| 单页文件 | `text-1p`，每页 | 1 个文件，直接下载不打包 |

**organize-pdf**（页面模式，已并入原旋转工具）

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 展开性能 | `text-60p-bookmarks` | 60 个缩略图渐进出现，滚动不卡 |
| 重排 + 旋转 | 拖动若干页、单页 ↻、「全部旋转」 | 输出页序与角度一致；缩略图旋转方向 = 输出方向 |
| 删页 | × 掉几页 | 输出少了对应页 |
| 已有旋转 | `mixed-sizes-rotations` | 自带 90°/180°/270° 的页再旋转是**叠加**，不是重置 |
| 输出名 | 留空 | `xxx_organized.pdf` |

**add-page-numbers**

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 6 个位置 | `text-5p`，tl/tc/tr/bl/bc/br | 页码出现在对应角，边距合理 |
| 6 种格式 | `1` / `1 / 5` / `- 1 -` / `Page 1` / 「第 1 页」/「第 1 页，共 5 页」 | 文案正确；中文格式要嵌入中文字体（不能是方块） |
| 起始与范围 | 起始号 3、从第 2 页开始 | 第 1 页无页码，第 2 页显示 3 |
| 旋转页 | `mixed-sizes-rotations` | 页码相对**看到的方向**摆正，不跑到页外 |
| 字号边距 | 调 size / margin | 视觉跟着变 |

**add-watermark**

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 平铺 vs 居中 | `text-5p` | 平铺铺满、居中只有一个 |
| 角度/透明度/字号/颜色 | 各调一次 | 与预览一致，正文仍可读 |
| 中文水印 | 文字填「机密文件」 | 中文正常显示 |
| 空文字 | 清空文字 | 友好提示 |
| 大页 | `poster-a0` | 水印比例正常，不会小成一点 |

**crop-pdf**

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 拖框裁剪 | `text-5p`，拖一个框，应用到全部页 | 所有页 CropBox 一致；内容没被拉伸 |
| 仅当前页 | 切到第 3 页拖框，范围选「当前页」 | 只有第 3 页变 |
| 混合尺寸 | `mixed-sizes-rotations` | 按比例映射，各页尺寸不同也不错位 |
| 巨幅 | `poster-a0` | 预览能渲染、裁剪正确 |

**delete-pages / extract-pages**

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 范围输入 | `text-5p`，`2, 5` | 删除：剩 3 页；提取：得 2 页一个文件 |
| 缩略图选择 | 不填范围，用界面选页 | 与范围输入一致 |
| 范围优先 | 同时填范围又点缩略图 | 以范围为准（当前实现） |
| 乱序重复 | 提取 `4-5, 2, 4` | 按文档顺序去重 → 2,4,5 |
| 全删 | 删除 `1-5` | 友好提示「至少留一页」 |

**edit-pdf**

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 四种标注 | `text-5p`：文字、高亮、白块、黑块各来一个 | 位置与预览一致；注意黑块只是画一个黑矩形，**底下的文字仍能被复制**（见「已知问题 1」） |
| 颜色 | 黑/红/蓝 | 文字颜色正确 |
| 多页 | 在第 1、4 页各加内容 | 互不串页 |
| 中文输入 | 文字框输入中文 / 日文 | 字体回退，不出方块 |
| 空编辑 | 什么都不加直接跑 | 输出等价原文件或给出提示（记录实际行为） |

**fill-pdf**

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 域枚举 | `form-acroform.pdf` | 列出 6 个可填域（`invoice.id` 只读，不出现）；类型对应：单行 / 6 位上限 / 多行 / 复选 / 单选 / 下拉（默认 Spain） |
| 长度上限 | `applicant.code` 输入 8 个字符 | 只能输 6 个 |
| 填写生效 | 各域都填，勾「扁平化」 | 输出用阅读器打开，内容在、且不可再编辑 |
| 不扁平化 | 取消勾选 | 输出仍是可填表单，值已预填 |
| 中文值 | 姓名填「张三」 | 正常显示（字体回退） |
| 无表单 | `text-5p` | 提示这个 PDF 没有表单域 |

### 转换类

**jpg-to-pdf / png-to-pdf**

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 多图合成 | `photo-landscape.jpg` + `photo-portrait.jpg` + `photo-square.png` | 3 页，顺序 = 卡片顺序 |
| 页面尺寸与方向 | 尺寸「贴合图片 / A4 / Letter」× 方向「自动 / 纵向 / 横向」 | 贴合时页面比例 = 图片比例；A4 时图片居中留白，方向按所选 |
| 边距、压缩、输出名 | margin 0 / 40；勾选压缩；输出名留空与自填 | 视觉正确；压缩后体积明显更小；文件名规则同 merge |
| EXIF 方向 | `photo-exif-rotated.jpg`、`photo-exif-rotated.png` | **按 EXIF 摆正**（应是竖版），不是横躺 |
| 没有 EXIF 的图不被重编码 | `photo-landscape.jpg` | 原始字节仍然直传（输出里能找到源文件字节），画质不打折 |
| 极端比例 | `panorama-4000x400.jpg`、`tiny-16px.png` | 不溢出页面；极小图不糊到不可接受 |
| 大图内存 | `photo-huge-6000x4000.jpg` | 能跑完，浏览器不崩 |
| WebP | `photo-webp.webp` | 正常（accept 里允许） |
| 透明 PNG | `signature-transparent.png` | 透明底渲染成白底而不是黑底 |
| 坏文件 | `bad/not-an-image.jpg` | 友好提示 |

**pdf-to-jpg / pdf-to-png**

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 分辨率 | `text-5p`，96 / 150 / 300 dpi | 像素尺寸成比例；文字清晰度可接受 |
| 格式 | jpg vs png | 扩展名与实际编码一致 |
| 页码范围 | `text-60p-bookmarks`，`1-3, 10` | 只导出 4 张 |
| 多输出打包 | 同上 | zip 内文件名带页码且排序正确 |
| 大文件 | `photos-12p` | 进度推进、能跑完 |
| 巨幅 | `poster-a0` 300 dpi | 要么成功，要么给出可读的「页面过大」提示，不能白屏 |

**pdf-to-text**

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 基本提取 | `text-5p` | 含重音字 `café / Grüße / Ærø`，段落不乱 |
| 中日文 | `cjk-text-2p` | 中文和日文都提取正确 |
| 页码范围 | `text-60p-bookmarks`，`5-6` | 只有这两页 |
| 分页标记 | 勾 / 不勾 | 勾选时有页分隔标记 |
| 扫描件 | `scanned-en-2p` | 结果为空 → 应引导去用 OCR（记录实际提示） |

**pdf-to-word**

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 基本转换 | `text-5p`，勾选图片 | `.docx` 能被 Word / Pages / Google Docs 打开，文字可编辑，版式大致对齐 |
| 不带图片 | `photos-12p`，取消勾选 | 输出明显更小，没有图片 |
| 带图片 | `photos-12p`，勾选 | 图片在，位置大致正确 |
| 中日文 | `cjk-text-2p` | 不出方块 |

**word-to-pdf**

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 富文本 | `office/report-rich.docx` | 2 页；标题样式、有序 / 无序列表、点导航（`Chapter one ...... 12`）、三列表格含合并单元格、图片、超链接可点、页眉 `Page 1 of 2`；中文和日文段落不出方块 |

| 坏包 | `bad/broken.docx` | 友好失败提示，不是堆栈 |

### 优化类

**compress-pdf**

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 轻度 | `photos-12p` | 体积变小；结果页显示压缩率 |
| 强力 × 三档 | `photos-12p`，72 / 110 / 150 dpi | 体积递增、清晰度递增；72 档明显更小 |
| 压不动 | `text-5p` 轻度 | **返回原文件**而不是更大的文件；压缩率显示 0% 或等价文案 |
| 内存 | `poster-a0` 强力 | 能跑完，不崩 |
| 文字保留 | `text-5p` 轻度后再用 pdf-to-text | 文字还在（轻度不该栅格化） |

**ocr-pdf**

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 英文 | `scanned-en-2p`，English，输出 PDF | 语言包首次下载（Network 里可见，二次走缓存）；输出可搜索，`INVOICE 2026-0917` 能搜到 |
| 西/德文 | `scanned-de`，Deutsch | `Müller`、`Gesamtbetrag` 识别正确；重音字不丢 |
| 日文 | `scanned-ja`，日本語 + 勾「同时识别英文」 | 日文识别可用 |
| 中文 | `scanned-zh`，简体中文 | 中文识别可用 |
| 纯文本输出 | 任一，输出选 .txt | 得到 txt 而不是 PDF |
| 跳过已有文字 | `mixed-text-and-scan-2p`，勾选 | 只 OCR 第 2 页（进度里看得出），第 1 页文字原样保留 |
| 不跳过 | 同上，取消勾选 | 两页都跑，耗时更长 |
| 默认语言 | 在 `/ja/ocr-pdf/`、`/zh/ocr-pdf/` 打开 | 语言下拉默认选中对应语种 |
| 巨幅 | `poster-a0` | 按上限缩放后能跑完 |

**repair-pdf**

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| xref 偏移写错（对象流结构） | `bad/broken-xref.pdf` | 修好，4 页都在，文字层还在（不是把页面拍成图） |
| xref 偏移写错（老式结构） | `bad/broken-xref-classic.pdf` | 修好，4 页都在 |
| 头部垃圾 600 B | `bad/junk-prefix.pdf` | 修好（qpdf 自己就能过） |
| 头部垃圾 2 KB | `bad/junk-prefix-2k.pdf` | 超出 qpdf 的 1 KB 搜索窗，靠 pdf-lib 兜底修好 |
| 缺 EOF | `bad/no-eof.pdf` | 修好 |
| 截断 | `bad/truncated.pdf` | 救回部分页，或给出清楚的失败说明 |
| 根本不是 PDF | `bad/not-a-pdf.pdf`、`bad/empty.pdf` | 友好失败，不发报错邮件 |

### 安全类

**unlock-pdf**

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 正确密码 | `encrypted-user-pw-open123.pdf` + `open123` | 输出 `_unlocked.pdf`，其它工具能直接处理 |
| 错误密码 | 同上 + `wrong` | 明确提示密码不对 |
| 不勾确认 | 勾掉授权确认 | 提示必须确认（合规要求，别漏） |
| 仅权限限制 | `encrypted-owner-only.pdf`，密码留空 | 直接去掉限制 |
| 老加密 | `encrypted-rc4-128-open123.pdf` + `open123` | 同样能解 |

**protect-pdf**

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 打开密码 | `text-5p` + 用户密码 | 输出在 Acrobat / 预览 里需要密码；再用 unlock + 该密码能解开 |
| 仅限制 | 只勾禁止打印 / 复制 / 修改 | 无需密码即可打开，属性里权限已受限 |
| 两个密码相同 | user = owner | 友好提示必须不同 |
| 什么都没填 | 全空 | 友好提示 |
| 中文密码 | 用户密码填中文 | 记录行为：能设就要能解，不能设就要提示 |

**sign-pdf**

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 手写 | `text-5p`，画板写一笔（鼠标 + 触屏各一次） | 笔迹平滑；空白画板直接签 → 友好提示 |
| 打字 | 三种字体样式 × 黑 / 蓝墨水 | 样式明显不同 |
| 图片 | `images/signature-transparent.png` | 透明底保留，不带白框 |
| 纸上照片 | `images/signature-on-paper.jpg` + 勾「去掉白底」 | 背景变透明、笔迹保留；不勾时是白底块 |
| 定位 | 拖动 + 缩放签名，翻到第 4 页放置 | 输出位置与预览一致（比例定位，换缩放级别也要对） |
| 所有页 | 勾「每页都签」 | 5 页都有，位置一致 |
| 旋转页 | `mixed-sizes-rotations` | 签名跟着看到的方向摆，不倒置 |

### 本轮修掉的

- **图片转 PDF 忽略 EXIF 方向**（2026-09-20 修）。原因在 `src/tools/jpg-to-pdf.ts` 的 `loadImage()`：JPG/PNG 且不压缩时原始字节直传，而 PDF 不认 EXIF，手机竖拍的照片就躺倒了。现在先用 `readExifOrientation()` 读一眼（JPEG 的 APP1 和 PNG 的 eXIf 都认），方向是 1 或没有这个信息才直传，否则走 canvas 重绘摆正（不压缩时质量给 0.92）。解析函数有单元测试（`test/new-tools.test.ts`），端到端有 `jpg2pdf/exif-orientation`、`exif-orientation-png`、`passthrough-not-reencoded` 三条用例守着。

- **加密 PDF 漏出 pdf-lib 的开发者错误**（2026-09-20 修）。原来界面上显示的是「Input document to \`PDFDocument.load\` is encrypted. You can use \`PDFDocument.load(..., { ignoreEncryption: true })\`…」，八种语言下都是这句英文，也不说该怎么办。现在 `src/lib/errors.ts` 的 `isEncryptedError()` 统一认出 pdf-lib / pdf.js 的这几种原文，`tool-app.ts` 换成当前语言的一句话 + 一个指向本语言解锁工具的链接；run()、页面展开、自定义工作区三条出错路径都走这个。顺带把 pages 模式打不开文件时二次抛出的异常收掉了（原来会变成控制台里的未捕获 rejection）。
- **修复工具修不了最常见的坏法**（2026-09-20 修）。`startxref` 偏移写错、`%%EOF` 完好的文件，qpdf 直接退出码 2，界面显示「damaged beyond repair」。现在 `src/tools/repair-pdf.ts` 加了第二道防线：qpdf 认输时让 pdf-lib 再读一次（它对坏 xref 宽容得多），读通就重新存一份，再交给 qpdf 规整，输出和正常路径一致。连原先修不了的「头部 2 KB 垃圾」也一并救回来了。
